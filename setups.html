Library · the Muse app

Setups

A Setup is what you change in the Muse app to make it better at a job. It has six parts. You can copy any of them from another owner by hand.

Sharing a Setup isn't built yet. For now this page is Mabel's notes on each part, and on the settings that matter for Week 1. Nothing here is counted from real runs. When sharing opens in Phase 2, a run can carry the Setup behind it.

Muse is rolling out in the US first, on iOS, Android and muse.ai (Meta newsroom). Using Muse Code, Meta's developer CLI? Its skills are the other track: Skills.

The six parts of a Setup

You write

Prompt recipes

The words you give Muse, step by step. Copy a recipe, run it, and keep the version that works. The Playbook has 28 community workflows to start from.

Connector

Connectors

The apps Muse can reach, such as Gmail and Google Calendar. Add them under Settings > Connectors. Write down which ones you use; that is the part other owners copy.

Sources: connectors · get started

You write

Custom connectors

For a service with no built-in connector. Muse can write its own connector for a service that has an API or a command-line tool. A shareable spec says which API, how to sign in, and the instruction you gave Muse. Never put a key or password in a spec.

Source: Meta research blog

Setting

Permission levels

Connectors and Web access each have a permission level. “Ask for some actions” asks you before write actions, such as sending an email. Set it before L3.

Source: permissions

Built in

Scheduled tasks

Ask in plain words, for example “Every Monday at 9am, remind me…”. A shared task is the sentence you used and when it runs.

Source: scheduled tasks

Built in

Personality and memory

You can rename your Muse, set its personality and how it answers, and tell it what to remember, such as “always cite the page you read”. You can also edit what it remembers. Muse may still remember what it learned from something you delete.

Sources: personalize Muse · your data

The diagnostic index

If you stalled at…

The pack is a diagnostic. Find where your agent stopped, then change one part of your Setup and retry.

  • Stalled at L1? Muse has a built-in browser, so this is rarely missing tools. → Check the Web access permission level, and ask it to name the page it took the number from.
  • Stalled at L2? It finds things but can't plan a research pass. → Ask for a plan first (which sources, which claims), then the brief. Ask it to open and read each source, not just the search results.
  • Stalled at L3? No working connectors, or sloppy procedure. → Connect calendar and email under Settings > Connectors, set Connectors to ask before actions, and read the safety rule twice.
  • Stalled at L4? It can't hold constraints or verify its own answer. → Prompting discipline: restate constraints, filter explicitly, check the winner against every one.
  • Stalled at L5? It can't ship a finished artifact. → Ask for exactly that: “one HTML file that opens in a browser.” Artifacts are built in and saved to your Library.

Coming in Phase 2

How sharing will work

This is the plan. It isn't built, and the details may change.

  • When you file a run, you can add the Setup behind it: the connectors you used (picked from a list of real Muse connectors), any custom-connector specs, your permission levels, your scheduled tasks, and what you changed this week.
  • You choose whether it is published. Nothing is published by default.
  • Each shared Setup is read before it is listed. A spec that holds a key, a password or hidden text is refused.
  • This page will then show which settings runs used, with the number of runs behind each one. No numbers are shown until there is data.
