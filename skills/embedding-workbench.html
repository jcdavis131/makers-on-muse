embedding-workbench

Reusable workbench for embedding models: validate vectors.json files, run k-NN queries by cosine similarity, and execute the champion-vs-challenger evaluation protocol. Triggers on 'embeddings', 'vectors.json', 'k-NN', 'challenger eval', 'champion vs challenger', 'validate vectors'.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Embedding Workbench

Purpose

One job: work with embedding vector files safely and repeatably — validate them, query nearest neighbors, and run the held-out champion-vs-challenger evaluation before anything is promoted. Built for the hoops embedding pipeline (MTNN v5 champion: 12,966 player-seasons × 64-d, assets/mtnn_embeddings.f32 in ~/workspace/vector-hoops), but format-flexible for any vectors.json-style file.

Tooling

bin/ (stdlib only — python3, no pip, no torch):

  • bin/validate_vectors.py — validate a vector file, print a compact report, exit 0/1.
  • validate_vectors.py vectors.json [--vec-field v] [--id-field id] [--rows-field players]
  • validate_vectors.py --f32 assets/mtnn_embeddings.f32 --rows 12966 --dim 64
  • Checks: row count, dimension consistency, non-numeric entries, NaN/Inf scan, L2-norm statistics (reported, not a failure — site-serving projections are not unit-normalized), duplicate-id scan.
  • bin/knn_query.py — top-k nearest neighbors by cosine similarity, single pass with heapq.nlargest (O(n log k)).
  • knn_query.py vectors.json --id <row-id> [-k 10]
  • knn_query.py vectors.json --vector "0.1,0.2,..." [-k 10]
  • knn_query.py --f32 assets/mtnn_embeddings.f32 --rows 12966 --dim 64 --id 0
  • The query row is excluded when querying by id. Cosine normalizes on the fly, so non-unit vectors work.
  • bin/vecio.py — shared loader (imported by the scripts, not run directly). Auto-detects the vector field (v, vector, embedding, vec, emb) and row container (players, rows, items, data); also handles bare row lists and top-level {id: vector} mappings.

Memory honesty: stdlib json has no true streaming parser, so a JSON file is loaded once; all per-row work after that is generator-based, so peak stays ~1x file size. The --id query path keeps rows in a list for its second pass (~1.2x); the --vector path is fully streaming. Files up to a few hundred MB are fine.

Workflow — champion-vs-challenger evaluation protocol

This is the exact protocol used when MTNN v6 failed against the v5 champion (top-1 0.0007 vs 0.118; continuity 0.507 vs 0.176 — v6 stayed research-only). Follow it verbatim for any challenger.

  1. Validate both files. Run validate_vectors.py on the champion asset and the challenger file. Both must exit 0. Record each file's sha256.
  2. Fix the held-out splits. Season-start-year splits: train ≤2021, val 2022–23, test ≥2024. Only val/test targets are truly held out — never train on them, never tune on test.
  3. Run held-out adjacent-season retrieval (the held_out_adjacent_season_retrieval metric): for each val/test player-season N, query the full space (self excluded, exhaustive — no sampling, pessimistic tie handling); a hit = that same player's season N+1 (keyed by stable NBA PLAYER_ID from the committed dashbase caches) ranks in top-k.
  4. Report, both models, same cohort: top-1 accuracy and recall@k on val and on test; continuity (lower is better — champion 0.176); nearest-neighbor cosine statistics. Same code path for both models — never hand-tune per model.
  5. Promotion rule. The challenger is promoted only if it beats the champion on all primary metrics on both val and test. Anything less → it stays research-only under its versioned filename (e.g. mtnn_v6_concat_b3_h256_t64_d128_mlp256_fus512_12452rows). A single-metric win is not a promotion.
  6. Record the decision. Winner, metrics table, both sha256s, and date go in the model registry (~/workspace/registry/); the full scoreboard mirrors the eval_scoreboard*.json convention in vector-hoops/public/assets/.

Output Contract

  • Validation: the script's printed report (rows, dim, norm stats, failure counts, verdict) plus exit code.
  • k-NN: ranked id / cosine / label lines, query echoed on the first line.
  • Eval: a metrics table (model × split × metric), the promotion decision with reasoning, and registry/scoreboard file paths written.

Operating Rules

  1. Never overwrite the production champion file (assets/mtnn_embeddings.f32, champion vectors.json). Challengers live under versioned filenames only.
  2. Never promote without a held-out win per the protocol above — no exceptions, no "looks better" promotions.
  3. Real data only. If a file is missing or corrupt, fail honest (the scripts exit non-zero) — never synthesize vectors to fill a gap.
  4. Champion identity is pinned: MTNN v5, mtnn_v5_concat_b2_h160_t32_d64_mlp128_fus256, 12,966×64. If a run reports different rows/dim for the champion file, stop and investigate — do not "fix" it by editing the file.
  5. English or code only. Zero-deps: if a step seems to need numpy/torch, find the stdlib way or stop and ask.
