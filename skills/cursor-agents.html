Agent Skills · Dev · Custom

cursor-agents

Dispatch headless Cursor coding agents (cursor-agent CLI) on local repos: one-shot runs, worktree-isolated fixes, read-only ask/plan modes. Use when the user wants Cursor agents doing repo work.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Cursor Agents

Run Cursor's coding agent headlessly from this machine via the official cursor-agent CLI (installed 2026-09-10, ~/.local/bin/cursor-agent, also as agent). This is the programmatic counterpart to cursor.com/agents (the cloud dashboard) and the @Cursor Slack seat in #agent-ops.

When to use

  • The user asks for Cursor to do repo work (fix, build, explore, review).
  • A second-model perspective on code (Cursor default model; pin with --model).
  • Isolated fix attempts: --worktree runs in a fresh git worktree without

touching the working tree.

Prefer the @Cursor Slack seat when the deliverable is a GitHub PR from a cloud agent. Prefer the Forge queue when the work needs the GPU node GPU. Prefer doing it directly (no Cursor) for anything cheap.

Auth

CURSOR_API_KEY is injected at runtime from the Secure Vault entry custom.cursor via an hsurr:* surrogate — the wrapper never sees the raw key. Never ask the user to paste a key in chat, never export it, never write it to a file. If auth fails:

  1. Re-run bin/cursor-setup to confirm the failure is auth, not install.
  2. Only then call credentials.request_api_access with reconnect to

replace the custom.cursor credential.

Get the key from the Cursor dashboard: cursor.com → Settings → API keys. It bills the user's Cursor plan (usage-based / on-demand must be enabled — the dashboard shows "usage limits reached" when it isn't).

Commands

# health: install + auth
bin/cursor-setup

# one-shot headless run (JSON output, run log saved under runs/)
bin/cursor-run --repo ~/workspace/vector-hoops \
  --prompt "Fix the off-by-one in assets/pack.js; run the existing tests."

# read-only exploration (no edits, cheapest way to verify auth + plumbing)
bin/cursor-run --repo ~/workspace/dottie --mode ask \
  --prompt "List the top-level directories and what each is for."

# planning only, no edits
bin/cursor-run --repo ~/workspace/dottie --mode plan \
  --prompt "Propose a plan to add request-id logging to the API."

# isolated worktree (does not touch the working tree)
bin/cursor-run --repo ~/workspace/vector-hoops --worktree fix-pack-js \
  --prompt "Fix the off-by-one in assets/pack.js."

# pin a model / pass raw flags through
bin/cursor-run --repo ~/workspace/dottie --model composer-2 --timeout 1800 \
  --prompt "..." -- --force

Flags: --repo DIR (required; becomes --workspace), --prompt TEXT or --prompt-file F, --mode ask|plan, --model M, --worktree NAME, --timeout SEC (default 1200), -- passes the rest straight to cursor-agent. Always passes --trust and --output-format json.

Rules

  • Every run bills Cursor usage. Say so when dispatching non-trivial work.
  • Default to --mode ask for scouting; only run full-agent mode when the

user asked for changes.

  • --worktree for any edit run on a repo with uncommitted work.
  • Verify the result yourself (read the diff / run the tests) before

reporting success — a Cursor exit 0 is not proof.

  • Run logs live in runs/ (prompt, args, exit code, stdout JSON, stderr

tail). Never put keys in them — there are none to put; the key is a surrogate resolved at the network edge.

  • Report to #agent-ops via ~/workspace/slack/report.py (--who cursor,

--event cursor:<short-id>): one line when a run starts (repo + task), one ≤10-line verdict when it finishes or fails. No report for pure read-only scouting under a minute.

Notes

  • Binary endpoint default: https://api2.cursor.sh (CURSOR_API_ENDPOINT

overrides). Cloud dashboard agents (cursor.com/agents) additionally require the user's Privacy Mode to allow code storage; local CLI runs do not — code stays on this machine.

  • cursor-agent update upgrades the binary; pinning is via

~/.local/share/cursor-agent/versions/.
