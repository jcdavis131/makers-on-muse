phone-live-transcript

Watch an in-progress phone call and get its transcript to the user as early as possible, with live status narration while the call runs. Triggers on 'show me the call transcript', 'stream the call', or watching an active phone call for the user.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Phone Live Transcript

Purpose

Give the user the transcript of a phone call at the earliest moment it exists, and narrate the call's live status while it runs. Honest limit up front: the provider releases the transcript only after the call ends — true mid-call text streaming is not possible today. This skill implements the best achievable behavior: a bounded poll loop with status updates, then immediate transcript delivery the moment it lands.

Workflow

  1. Get the call_id. Use the one returned by phone.place_call, or phone.list_calls (unfiltered, truncated: false) to find a recent one if it isn't in context.
  2. Start the watch: call phone.call_status with the call_id once to get the baseline state.
  3. Poll loop while status is non-terminal (queued, dialing, ringing, in_progress):
  • Wait 20–30 seconds between checks (never poll faster than ~15 s).
  • If the status changed since the last check, tell the user in one short line (during a voice call this becomes a spoken update: "still ringing", "connected now", etc.).
  • If the result now carries transcript_available: true, transcript_artifact_available: true, or a transcript_widget token, break out of the loop immediately and go to step 4.
  • If the status reaches a terminal value (completed, failed, canceled, rejected), allow one short grace window (~60 s) for the transcript to materialize, then stop.
  1. Present the transcript: share it verbatim via the exact token the tool returned (never reconstruct it from memory, never invent one). If the user asked for its contents, read and summarize them from the delivered attachment.
  2. Future-proofing: if the provider ever returns partial transcripts mid-call, present new text as it arrives and keep a seen-cursor (last shown character count or last segment id) so re-polls append only deltas.

Output Contract

  • While the call runs: one short spoken/text status line per state change, nothing more.
  • When the transcript lands: deliver the transcript token/content immediately, no delay.
  • When the call ends without a transcript: say plainly the transcript never materialized, and summarize the known outcome from call_status (status, duration, disconnection reason) without inventing detail.

Operating Rules

  1. Never claim to show a live transcript when only status is available — honest 503 over fake success.
  2. Never invent transcript content, a transcript token, or call dialogue.
  3. The poll loop is bounded: terminal status plus a short grace window ends it. Do not poll in a tight loop and do not spawn a separate monitor to keep watching.
  4. Do not redial or place a replacement call because a transcript is missing — check phone.list_calls first.
  5. Keep one unanswered user question in flight during a live call; narrate status, don't interrogate.
  6. During a voice call, keep status updates to a single short line each — the user is listening, not reading.
