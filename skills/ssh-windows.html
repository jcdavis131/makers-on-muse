ssh-windows — SSH lane to the owner's Windows boxes over Tailscale

SSH management lane to the owner's Windows machines, reached directly over the Tailscale tailnet. No cloud relay, no ports on the public internet: the only path in is Tailscale's encrypted mesh.

Tailnet TCP only via tunnel proxy. Ordinary egress from this VM cannot reach the tailnet — direct ssh to a 100.x address fails with "Operation not permitted". The win-ssh wrapper routes SSH through the runtime tunnel proxy (HTTP CONNECT via socat, ${HTTPS_PROXY%:*}:3130), the same path the tailscale-ops skill uses. Never test this lane with a bare ssh; always use the wrapper.

Inventory

HostTailnet IPRole
windows-pc[tailnet-ip]Always-on Windows host; future Home Assistant VM host

Add rows here when new Windows machines join the tailnet.

Auth

  • Keypair: ~/workspace/ssh/windows-pc/id_ed25519 (ed25519, no passphrase, file

mode 600). Public half is embedded in ~/workspace/ssh/windows-pc/setup-windows-pc.ps1, which the owner runs once on the box in an Administrator PowerShell.

  • Private key never leaves this VM. Never print its contents in chat, logs, or

tool output.

Usage

# the owner's Windows username on windows-pc — set once per shell, or pass explicitly
export JCD_WIN_USER="jcd"   # confirmed 2026-09-24

~/workspace/skills/ssh-windows/bin/win-ssh windows-pc "hostname; whoami"

First-ever connection accepts the host key (StrictHostKeyChecking=accept-new on the wrapper). Confirm the server fingerprint with the owner out-of-band the first time; after that the known_hosts entry pins it and any change will fail closed.

What this lane is for

  • Read-only state checks: uptime, services (sc query), disk, memory, Hyper-V

VM state for the future Home Assistant VM.

  • Planned: manage the Home Assistant VM on windows-pc (start/stop, check state),

run approved maintenance commands.

Rules

  • Read-only requests never authorize mutation. State-changing commands

(service restarts, installs, file writes, reboots) need the owner's explicit approval, same as every other production action.

  • Never open port 22 to the public internet on any Windows box — tailnet only.
  • If SSH stops responding, check Tailscale first:

~/workspace/skills/tailscale-ops/bin/ts-status
