obsidian-skills

Your Obsidian vault, but the agent actually reads it.

What this is

A bundle of 5 tight skills, each with its own SKILL.md. This root is just orchestration — it lists them and tells you when to dive deeper.

The 5 sub-skills

  1. defuddle — skills/defuddle/SKILL.md — Extract clean markdown from web pages using defuddle parse <url> --md. Use instead of WebFetch for docs, articles, blogs. Prefer defuddle for anything that's not already .md.
  1. json-canvas — skills/json-canvas/SKILL.md — Create/edit .canvas files per JSON Canvas Spec 1.0. Nodes + edges, mind maps, flowcharts.
  1. obsidian-bases — skills/obsidian-bases/SKILL.md — Create/edit .base files: filters, formulas, table/card/list/map views. Valid YAML only, quote tricky strings.
  1. obsidian-cli — skills/obsidian-cli/SKILL.md — Drive a running Obsidian instance via obsidian CLI. Use when the vault is open. Run obsidian help — that's always current.
  1. obsidian-markdown — skills/obsidian-markdown/SKILL.md — Obsidian Flavored Markdown: wikilinks [[Note]], embeds ![[file]], callouts > [!type], properties, tags.

How to pick

  • User passes URL to read → defuddle
  • User says ".canvas file" → json-canvas, load its REFERENCES/EXAMPLES.md only if needed
  • User says "Bases" / ".base" → obsidian-bases, check FUNCTIONS_REFERENCE.md for formula syntax
  • User says "in my vault" + action → obsidian-cli
  • User says "fix my markdown" / "wikilink" → obsidian-markdown, then peek at CALLOUTS.md / PROPERTIES.md / EMBEDS.md

Cozy tactician take

Vault is a system. Notes are nodes, bases are queries, canvas is the map. One bend (a tag rename) ripples everywhere — use [[wikilinks]] internally so Obsidian tracks renames for you.

Progressive disclosure

Don't preload all 5 SKILL.md at boot. Read this bundle file, then load the single child skill you actually need.
