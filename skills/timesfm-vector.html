timesfm-vector

Integrate TimesFM-3 multivariate time-series foundation model for forecasting and train new models for vector embedding games. Triggers on timesfm, time series forecasting, multivariate forecast, vector games forecasting.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

TimesFM Vector

Purpose

Use Google TimesFM-3 (330M, multivariate, zero-shot) in our projects, fine-tune new models on our data, and ship forecasts into vector embedding games (hoops etc). Handles license gating and zero-deps fallbacks.

Tooling

  • timesfm[torch] pip package or timesfm3 module from github.com/google-research/timesfm
  • HuggingFace checkpoints: google/timesfm-3.0-pytorch (non-commercial), google/timesfm-2.5-200m-pytorch (Apache-2.0)
  • Python: torch, numpy
  • Local cache: ~/workspace/models/timesfm/

Auth

No auth needed for open weights. For BigQuery ML integration later, use gcloud auth.

Workflow

  1. License check: TimesFM-3.0 weights = non-commercial-license-v1.0 only. For any production/commercial game, use 2.5 (Apache-2.0) or train own. Flag this in every ship.
  2. Zero-shot spike (today):

``python from timesfm3 import TimesFM3Evaluator, ModelConfig config = ModelConfig(checkpoint_path="google/timesfm-3.0-pytorch", per_core_batch_size=16, device="cuda") forecaster = TimesFM3Evaluator(config) # contexts: np array (num_variates, context_len) e.g. player embedding dims over time # past_future_covariates: (num_cov, context+hor) e.g. schedule, rest days, holidays outputs = list(forecaster.predict_batch([target], horizon=24, past_only_covariates=[...], past_future_covariates=[...], return_quantiles=True)) ``

  1. Train new: fine-tune TimesFM-2.5 via HF Transformers + PEFT LoRA (see timesfm-forecasting/examples/finetuning/), or train lightweight patch-transformer inspired by TimesFM-3 architecture (patch 32, alternating temporal/variate attention, Contiguous Patch Masking single-pass).
  2. Vector game mapping:
  • Hoops: forecast embedding coords of players over season, team vol+3p, daily court 5x past->modern with covariates (injury report, b2b, opponent strength)
  • Generic: forecast cluster movement in embedding maps, similarity decay
  • Quantiles (0.1-0.9) -> game uncertainty bands, betting edges local-first
  1. Ship: export point+quantile forecasts to ~/workspace/goals/mlops-factory-train-check-ship/ format, verify offline, 40px mono nav, verifier ≥8.0

Operating Rules

  • Always surface license warning before prod ship.
  • Prefer 2.5 for prod until we have commercial 3.0 or our own weights.
  • Zero-deps first: if torch not available, use stdlib patch-tokenizer + stub forecast that returns honest 503, never fake data.
  • All pipelines full-scale real data only, no synthetic.
  • Log triple-write timeline 7-field on train/check/ship.
  • Keep taste: map-first 58/42, 72vh sticky, modular IIFEs.

Quick Preview to Build

Before any heavy install, show user:

  • Which game first (hoops recommended)
  • Which data slice (player embedding trajectory vs team stats)
  • Which model tier (2.5 prod vs 3.0 research spike)
