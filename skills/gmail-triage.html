gmail-triage

Inbox triage playbook: scan unread mail, classify by urgency, draft replies for approval, stay silent when nothing needs the user.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Gmail Triage

Read-only scan first. Never send without the user approving the exact text. Follow the gmail skill for every command; keep commands, queries, and ids out of user-facing replies.

Scan (bounded)

  1. List unread inbox candidates, metadata only (sender, subject, date), max 30. Prefer metadata and snippets before full bodies. Also include unread Google Voice voicemail transcripts (from voice-noreply@google.com) — these are the Alamo St Advisors secretary line; handle per the Firm line section below.
  2. Read full bodies only for items that look urgent or actionable from metadata. Transactional mail (receipts, alerts, direct people) outranks promotional/newsletter mail for extracting facts.

Classify

  • URGENT — needs the user today: security alerts about access they don't recognize, payment/charge failures, direct personal email needing a same-day reply, time-bound opportunities expiring within 48h, anything matching the user's explicit watch items.
  • ACTION — needs a reply or task but not today: direct questions from real people, bills, scheduling requests.
  • FYI — confirmations, receipts, money movement, score/credit alerts, delivery notices. Summarize in one line each; no reply needed.
  • NOISE — newsletters, promos, social notifications, feedback surveys. Count them; offer bulk unsubscribe or filters only when asked.

Known-context rule: before flagging something as new, check whether it's already on the user's radar from recent work (e.g., CI/deploy failure notices for a repo actively being worked). Fold those into "already known" instead of re-alerting.

Firm line (secretary lane)

Voicemail transcripts from the Alamo St Advisors line arrive as mail from voice-noreply@google.com. Full brain: ~/workspace/firm-buildout/secretary-line.md. Classify each transcript:

  • LEAD (wants advisory / asks about fit) → treat as ACTION with same-day weight: draft the callback and propose 2–3 intro-consult slots from the calendar. Surface to the user; never send unapproved.
  • CLIENT (existing engagement) or URGENT (time-sensitive, upset, legal/press mention) → surface immediately, exactly like URGENT mail.
  • ADMIN / SPAM (vendors, wrong numbers, robocalls) → file silently, no reply.

Security rules for this lane: caller phone numbers and transcript contents are PII. Never put a caller's number in a chat reply or the timeline JSONL (counts only). Full details go only to the firm's local records log. Never forward transcripts to any third party or service.

Act

  • URGENT: surface immediately with a one-line why. Draft a reply only when a reply is clearly the right move; the user approves exact text before anything sends.
  • ACTION: draft replies and hold them for the user's review batch. Never send on your own reading.
  • FYI/NOISE: summarize; do not touch the mailbox (no mark-read, archive, or trash) unless the user explicitly asks for cleanup.

Scheduled watch behavior

The inbox-triage-watch cron runs this scan a few times daily. On a scheduled run: report to the main chat ONLY if URGENT items exist. Otherwise append one timeline JSONL line (7 fields: nodeId, agentId, attempt, latency_ms, tokens_est, status, errorClass) to ~/workspace/timeline/ and end quietly with a one-line "no urgent mail" result.

Reply to the user in plain English

No commands, queries, label names, API fields, or message ids. Say "unread mail", "Promotions", "your inbox". After any send, name the person and subject, never an id.
