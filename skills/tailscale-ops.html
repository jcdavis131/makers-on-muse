tailscale-ops

Operate the owner's Tailscale tailnet from this VM: check join status, reach his machines (GPU node, Android phone, iPhone) over the tailnet through the TCP tunnel, and pair tailnet access with the Forge workflow. Triggers on tailnet access, Tailscale device questions, or reaching GPU node over Tailscale.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Tailscale Ops

Purpose: this VM joins the owner's tailnet as the client-only device muse. Use the tailnet to reach his machines directly over TCP.

Tooling

  • Always use the bundled connector CLI: /opt/hatch/bin/tailscale.
  • Never use ~/workspace/tools/tailscale/ (upstream client; blocked by this

VM's egress proxy — kept on disk for reference only, do not start it).

  • bin/ts-status — one-shot: join state, this device's tailnet IPs, peer list.

Auth / Join

  • /opt/hatch/bin/tailscale up prints a login.tailscale.com link. Show it

to the owner and ask him to open it — only he can approve the device. Re-running reprints the same link and extends the 5-minute approval wait.

  • /opt/hatch/bin/tailscale status confirms the join.
  • tailscale down disconnects and erases this VM's identity (fresh approval

needed to rejoin). It does not remove the device from the admin console — the owner deletes it there himself.

Reaching machines

  • Ordinary egress does not reach the tailnet. Go through the runtime tunnel

proxy on port 3130:

tunnel_proxy="${HTTPS_PROXY%:*}:3130"
curl --proxy "$tunnel_proxy" --fail-with-body "http://<tailnet-ip>:<port>/<path>"
  • TCP only. ping, traceroute, and UDP never cross the tunnel — a failed ping

means nothing; test with a TCP connection through the proxy.

  • Address peers by tailnet IP, or by MagicDNS name when his network enables it.

tailscale status lists peers and addresses.

  • Each tunnel request needs its own approval; web permission does not carry

over. If this device is not joined, or the address is not on the tailnet, the request fails closed — it never falls back to the public internet.

the owner's tailnet

See references/devices.md for the device inventory (GPU node, Android phone, iPhone) and what each is for. Fill in tailnet hostnames from tailscale status once joined.

Pairing with Forge

  • The Forge Git conveyor (~/workspace/forge, repo owner/forge-queue)

stays the job route to GPU node — no SSH, ports, or VPN needed.

  • Tailscale adds direct TCP to services on GPU node (e.g. a training job's

local dashboard, artifact fetch over HTTP) once both ends are joined. It does not replace the Forge queue.

Operating Rules

  1. Never put credentials in a command.
  2. This VM is client-only: it accepts no inbound connections and routes for

nobody. It cannot be reached from the tailnet.

  1. User-facing language: "your Tailscale network" or the machine name. Quote

raw 100.x addresses only when the owner asks for detail.

  1. If tailscale status says not connected, say so and offer the join link —

never invent reachability.

  1. The connector does not offer exit-node selection.
