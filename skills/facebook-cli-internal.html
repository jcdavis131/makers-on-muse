facebook_cli_internal

Use for personal text/photo/video posts, comments, and reactions with approval, Facebook events (save a draft event, edit or delete one the user created, RSVP), Facebook identity, the user's managed Pages (discover with pages list, read insights or post metrics, create Page drafts, approved posts and native schedules), moderation of pending posts, membership requests, participation requests, and spam in Facebook Groups where the user is an admin or moderator, and hiding a Marketplace listing from friends or showing it again. Use facebook_cli for event search and details, personal-profile reads, pasted Facebook URLs, and public or non-managed Pages.

Scrubbed of personal details for the public library. The full library is re-curated weekly.

Facebook Internal CLI

Use this internal-only CLI for personal text/photo/video posts, comments, and reactions, Facebook events, Facebook identity, the user's managed Pages, and moderation queues for Groups where the user is an administrator or moderator. Read Feed posts before creating a personal post, comment, or reply, or adding/removing your reaction. Read Events before creating, editing, deleting, or RSVPing to a Facebook event; find and read events with facebook-cli events search and facebook-cli events details.

Before commenting, read the exact target with facebook-cli post read, even when the user supplies a post ID. For a share link, decode it first, then read the returned URL. Before replying, also read the post's comments to identify the parent. Reuse successful reads already available for this request. Add each requested comment or reply once. A successful receipt completes the write: include its comment_url as a clickable link in the confirmation. Never repeat the write to obtain a link, verify success, or handle a later confirmation of the same request. Use read-only inspection if needed.

Personal posts use the current Facebook composer audience by default and show it with the exact text in native approval. When the user specifies an override, read post audiences and pass a returned ID or exact name with --privacy. Use server-provided choices, including saved custom audiences; do not assume Public is available or ask a separate audience question when none was requested. For a Page-scoped request, start with pages list and continue only when the requested Page is returned. A Page or post ID outside that managed-Page workflow, or a pasted Facebook URL for a public or non-managed Page, remains a facebook-cli read.

Read references/me.md before running the command. Read Group moderation before listing a moderation queue.

Identity Operating Rules

  1. Run facebook-cli-internal me without arguments.
  2. The command is read-only and outputs JSON. Do not pass a format flag.
  3. An empty JSON object means no Facebook account is linked.
  4. Do not infer any profile attributes beyond the returned identity fields.

Marketplace Listing Visibility

marketplace listing visibility --listing-id <id> --hide-from-friends true|false hides one of the user's Marketplace listings from their Facebook friends, or shows it to them again. Read Marketplace listing visibility before running it.

Page Workflows

The Page CLI checks professional consent before authorization or data access. If it returns PROFESSIONAL_CONSENT_REQUIRED with tool_family: pages, pause for the native Meta Business card. After consent, continue through a fresh Page command and normal approvals; do not run an Ads-helper preflight.

Read Page workflows before discovery, insights, draft creation/editing/deletion, or approved posts with photos and MP4 videos.

posts create supports --scheduled-publish-time <Unix-seconds> with text, photos, videos, and individual media captions in one approved operation. Use posts create --file ... --scheduled-publish-time ... when scheduling uploaded media; no preliminary draft save is needed. Existing native drafts publish also schedules the same draft with original attachments and no retained copy. A scheduled receipt is pending, not published. posts reschedule changes its native time; posts cancel-schedule retains the same post as an unpublished draft. Both support text-only, photo, video, and mixed-media posts, preserving original photos/videos, captions, and order. Every posts create and drafts publish command must pass the exact client-side acknowledgment --privacy PUBLIC; no other privacy value is supported.

For individual captions on Page photos/videos, use --media-caption INDEX=TEXT on pages drafts create, pages posts create, or pages drafts edit; read references/pages.md for order, clearing, and snapshot rules. Keep individual media captions separate from the post text where supported. New single-media posts share their caption with the post text; omit the caption or use identical text. Draft text/removal edits include exact resulting captions in approval. A single retained caption matching the old post text follows a text edit by default. Draft publication preserves approved captions. Do not drop a requested caption or add media to work around a limitation. If a confirmed publish or schedule returns media_captions_verified: false, report that the write completed and that the captions differ or could not be verified. Use the returned post identity/link for inspection; never publish again as a check.
